## Clarifications

### Session 2026-07-13

- Q: 공개 도메인은? → A: 기존 보유 도메인의 서브도메인 + cloudflared 터널 라우팅 (예: cleanjeju.<보유도메인>). ※ 구 도메인 jejucleanhouse.com(2027-06 만료, Route 53)이 팀에 살아있음을 확인했으나 AWS 계정 접근 불가로 기각 (2026-07-13)
- Q: 클린하우스(~2,300개소) 상세 페이지 단위는? → A: 읍면동 단위 묶음 페이지. 재활용도움센터(78개)만 개별 페이지 (thin-content 회피)
- Q: 제보 채널은? → A: 사이트 내 제보 폼 + 운영자 이메일 발송 (홈서버 기존 메일 발송 인프라 재사용)
- Q: 앱 배포는? → A: 추가 결정(2차) — PWA(설치형 웹앱)를 기본으로 하고 Android는 TWA로 Play Store 배포. iOS는 PWA 홈 화면 설치로 제공(순수 WebView 래퍼는 App Store 심사 4.2 최소 기능성 리스크로 v2 범위 제외). 앱 아이콘·스플래시·마이크로 애니메이션은 기존 로고 SVG 기반으로 신규 제작

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 주변 배출 장소 찾기 (Priority: P1)

제주 거주자(또는 관광객)가 사이트에 접속하면 현재 위치 주변의 클린하우스와
재활용도움센터가 지도에 표시되고, 오늘 버릴 수 있는 재활용 품목과 각 개소의
운영 상태(운영중/마감)를 즉시 확인할 수 있다. 명칭·주소로 검색하면 거리순으로
결과가 나온다.

**Why this priority**: 서비스의 핵심 가치이자 기존 기능의 계승. 이것만 있어도
쓸모 있는 MVP다.

**Independent Test**: 배포된 사이트에 모바일 브라우저로 접속 → 위치 권한 허용/거부
두 경로 모두에서 지도와 주변 개소가 표시되고, 오늘의 배출 품목 안내가 현행 규칙과
일치하는지 확인.

**Acceptance Scenarios**:

1. **Given** 제주 시내에서 위치 권한을 허용한 사용자, **When** 첫 접속, **Then** 현위치 중심 지도에 주변 개소 마커와 오늘 배출 가능 품목이 표시된다
2. **Given** 위치 권한을 거부한 사용자, **When** 첫 접속, **Then** 무한 로딩 없이 제주 중심 기본 지도가 표시되고 검색으로 탐색할 수 있다
3. **Given** 제주 밖에서 접속한 사용자, **When** 첫 접속, **Then** 제주 기본 뷰가 표시되고 "제주 외 지역" 안내가 노출된다
4. **Given** 지도 화면, **When** "한림"으로 검색, **Then** 명칭·주소에 한림이 포함된 개소가 거리순으로 리스트업되고 지도가 해당 영역으로 이동한다
5. **Given** 운영시간 15:00~04:00인 클린하우스, **When** 새벽 02:00에 조회, **Then** "운영중"으로 표시된다 (자정 넘김 처리)

---

### User Story 2 - 항상 최신인 데이터 (Priority: P1)

운영자는 아무 것도 하지 않아도 제주시·서귀포시 클린하우스와 재활용도움센터
데이터가 공공데이터 원본으로부터 주기적으로 자동 수집·정규화되어 서비스에
반영된다. 수집이 실패하면 마지막 정상 데이터가 유지되고 운영자에게 알림이 간다.

**Why this priority**: 현재 서비스의 최대 결함(2021년 박제 데이터)의 해결.
US1이 보여주는 내용의 정확성을 담보하는 전제 조건.

**Independent Test**: 파이프라인을 수동 1회 실행 → 원본 데이터와 산출물의 건수·
스키마·좌표 유효성이 리포트로 확인되고, 서비스 화면의 "데이터 기준일"이 갱신된다.

**Acceptance Scenarios**:

1. **Given** 스케줄된 수집 잡, **When** 정상 실행, **Then** 제주시·서귀포시 클린하우스 + 재활용도움센터 데이터가 단일 스키마로 정규화되어 서비스에 반영되고 기준일이 갱신된다
2. **Given** 원본 API 장애, **When** 수집 실행 실패, **Then** 서비스는 마지막 정상 데이터로 계속 동작하고 운영자에게 알림이 발송된다
3. **Given** 원본에 좌표 누락·형식 오류 행 존재, **When** 정규화, **Then** 오류 행은 격리·리포트되고 정상 행만 반영된다

---

### User Story 3 - 검색으로 유입되는 안내·상세 페이지 (Priority: P2)

"제주 쓰레기 배출 요일", "제주 재활용도움센터" 등을 검색한 사용자가 검색 결과에서
이 서비스의 안내 페이지·개소 상세 페이지로 직접 유입된다. 안내 페이지는 요일별
배출제 규칙(제주시/서귀포시 구분), 재활용도움센터 이용법, FAQ를 담고, 상세
페이지는 개소별 주소·운영시간·수거 품목·길찾기를 담는다.

**Why this priority**: Next.js 전환의 이유(SEO). 검색 유입이 생겨야 서비스가
발견된다.

**Independent Test**: 자바스크립트를 끈 크롤러 시점에서 안내·상세 페이지의 본문
텍스트가 HTML에 존재하고, sitemap·메타태그·구조화 데이터가 유효성 검사를 통과한다.

**Acceptance Scenarios**:

1. **Given** 검색엔진 크롤러(JS 미실행), **When** 안내 페이지 요청, **Then** 배출 규칙 본문이 HTML 응답에 포함되어 있다
2. **Given** 개소 상세 페이지, **When** 조회, **Then** 고유 URL·페이지별 title/description·주소·운영시간·길찾기 링크가 표시된다
3. **Given** 배포된 사이트, **When** sitemap.xml 요청, **Then** 모든 안내·상세 페이지 URL이 나열된다
4. **Given** 배출 규칙이 조례 개정으로 변경, **When** 규칙 데이터만 갱신, **Then** 코드 배포 없이 안내 페이지와 "오늘 배출 품목"이 함께 갱신된다

---

### User Story 4 - 모바일에서 쾌적한 사용 (Priority: P2)

사용자 대부분은 쓰레기를 들고 나가기 직전 모바일로 접속한다. 모바일 뷰포트에서
지도·검색·리스트·상세 정보가 한 손 조작으로 자연스럽게 동작한다(바텀시트 등
모바일 관행 UI). 데스크톱에서는 지도+사이드 패널 레이아웃으로 표시된다.

**Why this priority**: 실사용 맥락이 모바일 중심. 기존 앱은 데스크톱 고정
레이아웃이라 모바일 UX가 사실상 없었다.

**Independent Test**: 375px/768px/1440px 뷰포트에서 주요 플로우(접속→검색→
상세 확인)가 가로 스크롤·요소 겹침 없이 완료된다.

**Acceptance Scenarios**:

1. **Given** 375px 모바일 뷰포트, **When** 전체 플로우 사용, **Then** 가로 스크롤 없이 모든 기능에 도달 가능하다
2. **Given** 모바일에서 마커 탭, **When** 개소 선택, **Then** 화면 하단 시트로 요약 정보가 뜨고 상세 페이지로 이동할 수 있다

---

### User Story 5 - 일관된 최신 디자인 (Priority: P3)

사용자는 어느 화면에서든 일관된 컴포넌트·타이포·색상·다크모드를 경험한다.
디자인시스템(Astryx) 기반으로 화면이 재구성되어 2021년의 혼재된 UI(부트스트랩+
MUI+styled-components)가 제거된다.

**Why this priority**: 품질·유지보수성 개선이지만 기능 가치는 위 스토리들에
종속적이다.

**Independent Test**: 전 화면이 디자인시스템 컴포넌트·토큰으로 구성되고,
다크모드 토글 시 모든 화면이 깨짐 없이 전환된다.

**Acceptance Scenarios**:

1. **Given** 아무 화면, **When** 다크모드 전환, **Then** 지도 오버레이·카드·안내 페이지가 모두 다크 테마로 일관 전환된다
2. **Given** 코드베이스, **When** 스타일 의존성 검사, **Then** 레거시 UI 라이브러리(부트스트랩/MUI v4/styled-components) 의존이 없다

---

### User Story 6 - 앱으로 설치해서 쓰기 (Priority: P3)

배출일마다 사이트를 다시 검색하기 번거로운 상시 사용자는 앱처럼 설치해서 쓴다.
모바일 브라우저에서 "홈 화면에 추가"(PWA 설치) 안내를 받고, Android 사용자는
Play Store에서 앱으로 설치할 수 있다. 설치된 앱은 전용 아이콘·스플래시와 함께
독립 창(standalone)으로 열린다.

**Why this priority**: 재방문 사용자 리텐션. 웹 v2가 완성된 뒤에 얹는 배포 채널
확장이라 기능 스토리들에 종속적이다.

**Independent Test**: Android 실기기에서 Play Store(내부 테스트 트랙) 설치 →
전용 아이콘으로 실행 → 주소창 없는 standalone 창에서 US1 플로우 완료.
iOS Safari에서 홈 화면 추가 → 동일 확인.

**Acceptance Scenarios**:

1. **Given** 모바일 브라우저 사용자, **When** 재방문, **Then** 설치 유도 UI가 노출되고 설치 시 홈 화면에 앱 아이콘이 생긴다
2. **Given** 설치된 앱, **When** 실행, **Then** 스플래시 → standalone 창으로 열리고 전 기능이 웹과 동일하게 동작한다
3. **Given** 오프라인 상태에서 앱 실행, **When** 네트워크 없음, **Then** 빈 화면 대신 마지막 데이터 기반 안내(오늘 배출 품목 등) 또는 오프라인 안내가 표시된다

---

### Edge Cases

- 위치 권한 거부/타임아웃/미지원 브라우저 → 기본 위치로 항상 동작 (현행 무한 로딩 버그 재발 금지)
- 운영시간이 자정을 넘는 개소(15:00~04:00)의 운영중 판정
- 원본 데이터 간 중복 개소(제주시/서귀포시 데이터셋 경계)와 좌표 (0,0)·바다 위 등 이상 좌표
- 공공데이터 API 폐기·URL 변경 → 수집 실패 알림으로 감지
- 검색 결과 0건 → 빈 상태 UI (현행 `alert()` 금지)
- 배출 규칙의 시별 차이(제주시 vs 서귀포시)와 공휴일·명절 임시 규칙
- 2,400+ 마커 동시 렌더링 시 지도 성능

## Requirements *(mandatory)*

### Functional Requirements

**데이터 (파이프라인)**

- **FR-001**: 시스템은 제주시 클린하우스, 서귀포시 클린하우스, 재활용도움센터 데이터를 공식 공공데이터 출처에서 자동으로(최소 주 1회) 수집해야 한다
- **FR-002**: 시스템은 수집 데이터를 단일 스키마(식별자, 명칭, 주소, 좌표, 유형, 운영시간, 수거함 구성, 출처, 수집시각)로 정규화하고, 검증 실패 행을 격리·리포트해야 한다
- **FR-003**: 시스템은 요일별 배출제 규칙(지역×요일×품목)을 코드가 아닌 데이터로 관리하고, 규칙 데이터 갱신만으로 전 화면에 반영해야 한다
- **FR-004**: 수집 실패 시 서비스는 마지막 정상 데이터로 계속 동작하고, 운영자에게 이메일로 알림해야 한다 (긴급 채널은 사용하지 않는다)
- **FR-005**: 모든 화면은 표시 중인 데이터의 기준일(수집 시각)을 노출해야 한다

**지도·탐색**

- **FR-006**: 시스템은 전체 개소를 지도에 마커·클러스터로 표시하고 유형(클린하우스/재활용도움센터) 필터를 제공해야 한다
- **FR-007**: 위치 권한 허용 시 현위치 중심으로, 거부·실패·제주 외 지역 시 제주 기본 뷰로 5초 이내에 지도를 표시해야 한다
- **FR-008**: 사용자는 명칭·주소로 검색할 수 있고 결과는 거리순으로 정렬되어야 한다
- **FR-009**: 개소별 운영 상태(운영중/마감)는 개소 데이터의 운영시간 기준으로 조회 시점에 계산되어야 하며 자정을 넘는 시간대를 올바르게 처리해야 한다
- **FR-010**: 사용자는 개소에서 길찾기(카카오맵 길찾기 연결)를 실행할 수 있어야 한다

**페이지·SEO**

- **FR-011**: 각 개소는 고유 URL의 상세 페이지(주소, 운영시간, 수거 품목, 지도, 길찾기)를 가져야 한다
- **FR-012**: 시스템은 요일별 배출제 안내 페이지(제주시/서귀포시 구분, 오늘 기준 강조), 재활용도움센터 안내, FAQ 페이지를 제공해야 한다
- **FR-013**: 콘텐츠성 페이지(안내·상세)는 자바스크립트 미실행 환경에서도 본문이 HTML로 제공되어야 한다
- **FR-014**: 시스템은 페이지별 메타태그, Open Graph, sitemap.xml, robots.txt, 구조화 데이터(JSON-LD)를 제공해야 한다

**UX/UI**

- **FR-015**: 모든 화면은 375px~1440px 뷰포트에서 반응형으로 동작해야 한다 (모바일 우선)
- **FR-016**: 전 화면은 단일 디자인시스템(Astryx)의 컴포넌트·토큰으로 구성되어야 하며 라이트/다크 모드를 지원해야 한다
- **FR-017**: 오류·빈 상태는 브라우저 `alert()` 대신 화면 내 UI로 안내해야 한다
- **FR-018**: 키보드 탐색, 충분한 명도 대비, 이미지 대체 텍스트 등 기본 접근성을 갖춰야 한다
- **FR-019**: 기존 개인 이메일(mailto) 신고 기능은 제거하고, 사이트 내 제보 폼으로 대체해야 한다. 제보는 운영자 이메일로 발송되며(홈서버 기존 메일 발송 인프라 재사용), 스팸 방지 장치(rate limit 등)를 갖춘다

**앱 배포·브랜드**

- **FR-022**: 서비스는 설치 가능한 PWA여야 한다 — 웹 앱 매니페스트(standalone, 아이콘 세트), 서비스 워커(오프라인 셸 + 마지막 데이터 폴백), 재방문 시 설치 유도 UI
- **FR-023**: 브랜드 자산 세트를 갖춰야 한다 — 기존 로고 SVG를 기반으로 재제작한 앱 아이콘(maskable 포함 전 규격), 파비콘, 스플래시, OG 이미지, 로딩·빈상태 마이크로 애니메이션
- **FR-024**: Android용 TWA 패키지를 Play Store에 배포해야 한다 (Digital Asset Links 검증 포함, 초기엔 내부 테스트 트랙)

**추가 기능 (2026-07-13 사용자 선정 — 구현 완료)**

- **FR-022a**: 사용자는 개소를 즐겨찾기(로컬 저장)하고, 홈에서 운영상태와 함께 원탭 이동할 수 있어야 한다
- **FR-022b**: 사용자는 "지금 열린 곳" 원탭으로 현재 운영 중인 가장 가까운 개소를 찾을 수 있어야 한다 (기준: 현위치, 거부 시 지도 중심)
- **FR-022c**: 시스템은 분리배출 품목 사전(17품목+)을 제공해야 한다 — 품목별 배출 장소·방법·주의, 요일제 품목은 규칙 데이터 연동, 개별 SEO 페이지
- **FR-022d**: 사용자는 배출일 푸시 알림을 구독할 수 있어야 한다 — 매일 배출 시작 시각(15:00 KST)에 당일 시별 품목 발송, 구독 해지·만료 정리 포함

**운영**

- **FR-020**: 서비스는 홈서버에서 단일 서비스 단위로 배포·재시작 가능해야 하며 HTTPS로 제공되어야 한다
- **FR-021**: 기존 보유 도메인의 서브도메인으로 공개 서비스되어야 한다 (cloudflared 터널 라우트 추가, 카카오 개발자 콘솔에 해당 도메인 등록)

### Key Entities

- **배출 장소 (Site)**: 클린하우스 또는 재활용도움센터. 식별자, 명칭, 주소(도로명/지번), 좌표, 유형, 운영시간, 수거함 구성(종량제/재활용/유리병/스티로폼/건전지/형광등/음식물 등), 관할(제주시/서귀포시), 출처, 수집시각
- **배출 규칙 (Disposal Rule)**: 지역(제주시/서귀포시) × 요일 × 배출 가능 품목. 시행일·출처 포함 — 조례 개정 시 이력 관리
- **데이터 스냅샷 (Snapshot)**: 1회 수집의 산출물. 기준일, 건수, 검증 리포트(성공/격리 행), 원본별 출처 URL

## Assumptions

- 기존 CRA 앱은 전면 대체한다 (점진 마이그레이션 아님). 단, 도메인 로직(거리 계산, 제주 경계 판정, 클러스터 파라미터)은 의도 파악 후 이관한다
- 상세 페이지 단위 확정: 클린하우스는 읍면동 단위 묶음 페이지(약 40여 개, 개소 목록·지도 포함), 재활용도움센터(78개)는 개별 페이지 — SEO thin-content 페널티 회피
- 데이터 수집 주기는 주 1회로 충분하다 (원본 갱신주기가 연간)
- Astryx는 Beta이므로 plan 단계에서 Next.js App Router 호환성을 검증하고, 불가 판정 시 대체 디자인시스템을 사용자와 재협의한다
- 지도는 카카오맵을 유지한다 (기존 키 보유, 국내 지도 품질). 신규 배포 도메인을 카카오 개발자 콘솔에 등록해야 한다
- 운영자 알림은 기존 홈서버 이메일 다이제스트 체계를 따른다
- (2026-07-13 변경) iOS App Store는 **Expo 웹뷰 래퍼로 제출 시도** (maeil-app 툴체인 재사용, 4.2 리스크는 네이티브 처리 세트로 완화, 리젝 시 네이티브 푸시 추가 후 재제출). Android TWA는 Play 계정 확보 시까지 보류
- Play Store 배포에는 Google Play 개발자 계정(1회 $25)이 필요하다 — 사용자 보유 여부 확인 필요
- 브랜드 자산은 기존 로고 SVG(Clean_house.svg 등)를 출발점으로 재제작하며, 애니메이션은 Lottie 또는 Rive 중 제작 도구 사정에 맞는 쪽을 선택한다 (plan 단계 결정)
